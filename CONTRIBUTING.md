# Contributing

This is a personal learning and portfolio project. The contribution process is intentionally structured like a small professional product team.

## Workflow

1. Pick or create a small issue.
2. Define acceptance criteria before coding.
3. Implement the smallest useful change.
4. Add or update tests when behavior changes.
5. Update documentation if architecture or product behavior changes.
6. Commit with a clear message.

## Commit Style

Use short conventional commits:

- `docs: add product brief`
- `chore: scaffold monorepo config`
- `feat(api): add queue search endpoint`
- `test(api): cover alert detector`
- `fix(web): handle empty queue results`

## Learning Rule

For every meaningful feature, add a short note to `docs/12-learning-log.md`:

- what was built
- what concept was learned
- what trade-off was made
- what interview question could come from it

## AI Assistance Rule

AI can be used for explanation, review, task breakdown and implementation support. The final code owner must be able to explain:

- why the solution was chosen
- how it works
- what alternatives were considered
- what limitations remain
